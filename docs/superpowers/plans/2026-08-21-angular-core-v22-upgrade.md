# Angular Core v22 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the Angular framework from 20.3 to 22.1 across this npm-workspaces monorepo, pinning TypeScript to the exact version Angular 22 requires, with ng-select and every other dependency left untouched.

**Architecture:** Two sequential `ng update` major-version hops (20→21, 21→22), each its own commit, each independently verified via lint/test/build/build:electron before moving on. No new code is written; this is a dependency + generated-migration change.

**Tech Stack:** Angular 22 (`@angular/core`, `cli`, `cdk`, `common`, `compiler`, `compiler-cli`, `forms`, `platform-browser`, `router`, `localize`, `build`), `@angular-eslint/*`, TypeScript ~6.0.0, npm workspaces (Angular workspace root is `packages/app`, dependencies are hoisted to the repo-root `package.json`).

**Spec:** `docs/superpowers/specs/2026-08-21-angular-core-v22-upgrade-design.md`

## Global Constraints

- Target versions: `@angular/core`, `common`, `compiler`, `compiler-cli`, `forms`, `platform-browser`, `router`, `localize` → `^22.1.3`; `@angular/cdk` → matching 22.x; `@angular/cli`, `@angular/build` → `^22.1.3`; `@angular-eslint/*` → matching 22.x line.
- `typescript` must end at exactly `~6.0.0` (Angular 22's compiler-cli peer range is `>=6.0 <6.1`) — never let it float to the npm `latest` tag (currently 7.0.2, which is incompatible).
- `@ng-select/ng-select` stays pinned at `^20.7.0`. Do not let `ng update` or `npm install` touch it. It is out of scope for this issue.
- No other dependency (`ag-grid-angular`, `better-sqlite3`, `electron`, `bootstrap`, `ng-bootstrap`, etc.) changes in this plan.
- `npm run lint` runs ESLint with `--max-warnings=0` — zero warnings tolerated, not just zero errors.
- Commit message format: `#269: short description` (this repo's convention; see root `CLAUDE.md`).
- Use `-` (hyphen), never `—` (em dash), in commit messages and any written output.
- Angular workspace root (`angular.json`) is at `packages/app/`, but `@angular/*` package versions live in the **repo-root** `package.json` (npm workspaces hoist them — verified: `packages/app/package.json` declares only `@bitbutler/shared` as a dependency).
- The `docs/superpowers/` folder must never be merged to `main` — it gets removed in its own final commit before the PR is opened (per root `CLAUDE.md`).

## Task 1: Upgrade to Angular 21

**Files:**

- Modify: `package.json` (repo root) — `@angular/*`, `@angular-eslint/*` versions
- Modify: `package-lock.json` (repo root) — regenerated by `ng update`
- Modify: whatever files the `ng update` migration schematics touch (unknown until run — inspect `git diff` after and include everything it changed)

**Interfaces:** N/A (dependency upgrade, no new code contracts)

- [ ] **Step 1: Run the Angular 21 update from the Angular workspace root**

Run from `packages/app` (where `angular.json` lives), since `ng update` needs to detect the Angular workspace:

```bash
cd packages/app
npx ng update @angular/core@21 @angular/cli@21 @angular/cdk@21
cd ../..
```

- [ ] **Step 2: Verify the repo-root `package.json` was updated, not a workspace-local one**

```bash
git status --short
git diff package.json | head -60
```

Expected: `package.json` at the repo root shows the `@angular/*` and `@angular-eslint/*` lines bumped to `21.x`. If instead `ng update` wrote a new `dependencies` block into `packages/app/package.json`, manually move those version bumps into the root `package.json` (matching the existing `^` prefix style already used there), delete the erroneous entries from `packages/app/package.json`, then run `npm install` from the repo root to reconcile `package-lock.json`.

- [ ] **Step 3: Review what the migration schematics changed**

```bash
git diff --stat
```

Read through every non-`package.json`/`package-lock.json` file in the diff (these are Angular's automated migrations — e.g. import path updates, config flag renames). Confirm each change looks intentional and scoped to the migration; nothing here should touch application logic.

- [ ] **Step 4: Run the full verification suite**

```bash
npm run lint
npm test
npm run build
npm run build:electron
```

Expected: all four exit 0. `npm run lint` must report zero warnings (not just zero errors — `max-warnings=0` is enforced).

If any command fails: read the actual error message first. For lint issues, try `npm run lint:fix` before hand-editing. For TypeScript compile errors surfaced by the migration, check the specific item at https://angular.dev/reference/migrations before changing application code — the fix is almost always aligning with what the migration schematic expected, not rewriting logic. For test failures, isolate the failing spec with `npx vitest run <path/to/file.spec.ts>` from `packages/app` to see the full diff. Do not proceed to Step 5 until all four commands are clean.

- [ ] **Step 5: Commit**

```bash
git add -A
git commit -m "$(cat <<'EOF'
#269: upgrade Angular framework to v21

EOF
)"
```

## Task 2: Upgrade to Angular 22 and pin TypeScript

**Files:**

- Modify: `package.json` (repo root) — `@angular/*`, `@angular-eslint/*`, `typescript` versions
- Modify: `package-lock.json` (repo root) — regenerated
- Modify: whatever files the `ng update` migration schematics touch (unknown until run, including the `OnPush`-default migration, which will edit component decorators across `packages/app/src/`)

**Interfaces:** N/A (dependency upgrade, no new code contracts)

- [ ] **Step 1: Run the Angular 22 update**

```bash
cd packages/app
npx ng update @angular/core@22 @angular/cli@22 @angular/cdk@22
cd ../..
```

- [ ] **Step 2: Verify the repo-root `package.json` was updated correctly**

Same check as Task 1 Step 2 — confirm `@angular/*`/`@angular-eslint/*` land in the root `package.json` at `22.x`, correcting manually if `ng update` wrote to the wrong file.

- [ ] **Step 3: Pin TypeScript to the exact version Angular 22 requires**

```bash
npm view @angular/compiler-cli@22.1.3 peerDependencies --json
```

Confirm the `typescript` range printed is `>=6.0 <6.1` (if a newer Angular 22.x patch has shifted this range, adjust the target version below accordingly — the goal is "whatever exact `6.0.x` `ng update` resolves peer-compatibility against," not literally `6.0.0` if a later patch is out).

Check what version is currently installed:

```bash
grep '"typescript"' package.json
```

If it is not inside the `>=6.0 <6.1` range, edit the root `package.json` directly to set it explicitly, e.g.:

```json
"typescript": "~6.0.0"
```

Then reinstall:

```bash
npm install
```

- [ ] **Step 4: Review the `OnPush` migration diff**

```bash
git diff --stat packages/app/src
```

Angular 22 defaults new components to `ChangeDetectionStrategy.OnPush`; the migration schematic should have added `ChangeDetectionStrategy.Eager` to every existing `@Component` decorator that didn't already specify a strategy, so behavior doesn't silently change. Spot-check a handful of the changed component files to confirm `changeDetection: ChangeDetectionStrategy.Eager` was added (or `OnPush` was left alone where a component already declared it) rather than components being silently switched to `OnPush`.

- [ ] **Step 5: Run the full verification suite**

```bash
npm run lint
npm test
npm run build
npm run build:electron
```

Same expectations and troubleshooting approach as Task 1 Step 4 — zero warnings, all four green before moving on. Additionally check for TypeScript 6.0 compiler errors: `npm run build` runs `tsc` as part of the Angular build, so any TS 6.0 syntax/strictness changes will surface here.

- [ ] **Step 6: Manual smoke test of the Electron app**

```bash
npm start
```

Wait for the Angular dev server, `tsc:watch`, and Electron to all report ready in the concurrently output, then in the launched app window:

1. Confirm the login page renders (no blank screen, no console errors in Electron DevTools).
2. Log in to (or select) a configured server and confirm the main torrent grid renders.
3. Open any settings modal (e.g. General settings) and confirm it opens and closes without visual breakage.

This is a smoke test only — ng-select dropdown behavior is explicitly out of scope for this issue (tracked in the follow-up ng-select upgrade) and does not need a full audit here. Stop the dev server (Ctrl+C) once confirmed.

- [ ] **Step 7: Commit**

```bash
git add -A
git commit -m "$(cat <<'EOF'
#269: upgrade Angular framework to v22 and pin TypeScript to 6.0

EOF
)"
```
