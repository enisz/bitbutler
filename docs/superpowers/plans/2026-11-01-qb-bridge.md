# Typed qBittorrent Bridge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the generic `window.bitbutler.qb.request` proxy with 56 typed, intent-level IPC methods that return `IpcResult<T>`, so the renderer never sees a qBittorrent URL, version or HTTP status.

**Architecture:** `@bitbutler/shared` defines the contract (`BitButlerQbAPI`, `IpcResult`, `QbErrorCode`). A new `packages/electron/src/qb/` layer owns endpoints, version rules, re-login and error mapping, and every main-process caller (tray, export, torrent-add-queue) uses it. One IPC channel (`qb:call`) dispatches to an allowlisted registry; `QbService` becomes a thin wrapper that unwraps results into a thrown `QbError`.

**Tech Stack:** Electron main (TypeScript, better-sqlite3, `fetch`), Angular 22 zoneless, Vitest (electron), `ng test` (app), npm workspaces.

**Spec:** `docs/superpowers/specs/2026-11-01-qb-bridge-design.md` (read it first; it holds the reasoning and the decisions this plan applies).

## Global Constraints

- Branch `380-typed-qb-bridge`, issue #380. Commit format `#380: short description`; commit bodies end with the attribution trailer from the session. Use `-` not `—` in all written output.
- Electron may only `import type` from `@bitbutler/shared` (the compiled main process cannot resolve its `.ts` source at runtime). The Angular app may import values (enums) from it.
- Lint is `--max-warnings=0`. Run `npx prettier --write` on touched files before committing (Husky does it too).
- `packages/app` must not contain the string `/api/v2` or any HTTP status number in non-spec code when finished.
- Bridge method parameter lists equal the `QbService` method of the same name today (`serverId` first), except `pause`/`resume` are `stop`/`start`. `QbService`'s own public API does not change.
- Empty-input behaviour is preserved per method: a no-op success for empty hash lists on most methods; `INVALID` for blank `hash`/`location`/`name`/`ids` and empty hashes on `setLocation`, `delete`, `setShareLimits` (mirror the current `QbService` code per method).
- Codes: `UNAUTHENTICATED`, `FORBIDDEN`, `NOT_FOUND`, `CONFLICT`, `UNREACHABLE`, `UNSUPPORTED`, `INVALID`, `FAILED`.
- WebAPI >= 2.11.0 uses `torrents/start`/`stop`; below that or unknown, `torrents/resume`/`pause` first; a 404 on the first pair retries the other pair; the pair that worked is cached per server in memory.
- Test commands: electron `npm run test --workspace=packages/electron -- <file>`; app `npm run test --workspace=packages/app -- --include=<spec path>`; type check `npx tsc --noEmit -p packages/electron/tsconfig.json`.

## Review Focus

- Both endpoint pairs return 404 -> `UNSUPPORTED` (not `NOT_FOUND`) and the user sees a failure toast (Task 4, Task 11).
- Session expires mid-use: one silent re-login + one retry is transparent; if re-login fails the renderer gets `UNAUTHENTICATED` and logs out exactly once (Task 2, Task 11).
- The login-time version/export probe fails or the server lacks `/app/webapiVersion`: login still succeeds, version stays null, resume/pause still work via the fallback (Task 3).
- The `qb:call` handler never rejects: unknown method name, non-array args, and non-`QbBridgeError` throws all come back as `{ ok: false }` (Task 8).
- Transient failures: the renderer retries `UNREACHABLE` up to 3 times with the retry warning toast and then fails; a duplicate add (HTTP 409 -> `CONFLICT`) still shows the "duplicate" job status (Task 10, Task 11).
